# Engineering rules

Priorities, in order: correctness → simplicity → consistency with existing code → security → testability → reuse → performance (only when measured).

## Principles, as applied here

- **DRY is for knowledge, not look-alike code.** Keep each business rule in one place (the engine) and each contract in one place (`contracts`). Two similar-looking mappers in two modules are fine.
- **No ceremony.** No repository interfaces, factories or "managers" around a single implementation. The `*.client.ts` files already are the data-access seam, so don't wrap Prisma again.
- **YAGNI.** Don't add extension points, config flags or generic helpers without a present consumer. Write future concerns in `plans/ACTIVE.md`, not in code.
- **Extract when** a rule must stay in sync across real consumers, or a second real use appears.

## TypeScript

- `strict` + `noUncheckedIndexedAccess` (`packages/typescript-config/base.json`). Don't weaken them.
- Types come from Zod: `z.infer` in `*.model.ts` / `*.dto.ts`. Don't hand-write a type that duplicates a schema.
- Money is integer cents everywhere (`CentsSchema`). Format only at the edge (`formatCents`).

## contracts (`packages/contracts/src/<domain>/`)

- `*.schema.ts` holds Zod schemas, `*.model.ts` the inferred domain types, and `*.dto.ts` the request/response schemas. Each domain has an `index.ts` and an `exports` entry in `package.json`.
- Change the contract first, then the hub, then the web. The build fails anywhere the shape no longer matches.

## pricing-engine

- **No I/O**: no Nest, no Prisma, no `fetch`, no `Date.now()`. Time arrives as a `TradingMoment`.
- Every pricing behaviour change comes with a test in `engine.spec.ts` or `clash.spec.ts`. Use `src/testing/builders.ts` to build fixtures.
- Explanations (`applied` / `skipped` reasons) are part of the output contract. Wording changes are product changes.

## promo-hub (NestJS)

- **Adding a module:** copy the nearest sibling. Create `paths/<name>.ts` (enum of route strings), then the controller, service, client and module, and register it in `app.module.ts`.
- **Controllers:**
  - Decorate every route with `ApiEndpoint` / `apiResponse` from `@ridgeline/nest-common`. Importing `@nestjs/swagger` in a controller is a lint error.
  - Validate with `new ZodValidationPipe(Schema)` on `@Body`, `@Query` and `@Param`.
  - No logic beyond delegating to the service.
- **Services:** business orchestration, mapping to contract types, and Nest exceptions (`NotFoundException`, `BadRequestException`, `ForbiddenException`). They're async whenever they touch the database.
- **Clients:** the only files that call Prisma or `TrestleService`. They return domain or contract shapes.
- **Cross-module:** import the other module and inject its **exported service**.
- **Errors:** throw Nest HTTP exceptions from services. Convert engine errors (e.g. `UnknownProductError`) to HTTP errors at the service boundary.
- **Logging:** none beyond boot messages. Don't add `console.log` in request paths.

## Prisma (`apps/promo-hub/prisma/`)

- Change the schema → run `make migdev ARGS="--name <what>"` → commit the new migration folder. Never edit an applied migration.
- The generated client lives in `src/database/generated/`. It's gitignored and regenerated by `postinstall`, `build`, `test` and `make gen`. Never edit it.
- JSON columns must be written from, and read through, contract schemas (see `rulebooks/rulebook.mapper.ts`).
- Multi-row writes that must land together use `prisma.$transaction([...])` (see `RulebooksClient.save`).
- Versions of `prisma`, `@prisma/client` and `@prisma/adapter-better-sqlite3` are pinned to 7.9.1 in `pnpm-workspace.yaml`. Bump all three together, deliberately.

## promo-web (Next.js)

- **Structure:**
  - Routes: `app/<page>/page.tsx`. Route strings: `paths/app.ts`.
  - Feature components: `components/<feature>/`.
  - Data hooks: `lib/queries/*.ts` (React Query, one file per API area).
  - HTTP: `lib/api-client.ts` only.
- **Client components:** every page is currently a client component, because all data comes from React Query hooks. Keep `"use client"` at the page or interactive component. A new page with no interactivity can be a Server Component.
- **Mutations** go in `lib/queries/*` hooks and invalidate what they affect. Rule edits invalidate `rulebooks`, `rulebook`, `quote`, `impact` and `clash-grid`.
- **No business logic in React.** Components display what the API returns. `lib/format.ts` does display formatting only.
- **Known duplication:** `lib/format.ts` re-implements `formatCents`, `formatTime`, `describeDays` and `describeWindow` from the engine. If you change one, change both; don't add more copies.
- **Demo defaults:** hardcoded IDs (`VEN-0233`, `M-004182`, `STF-11`) are simulator presets. Don't spread them further.

## Dependencies

- Add every version to the `catalog:` in `pnpm-workspace.yaml` and reference it as `"catalog:"`. Justify every new dependency.
- Packages whose install scripts must build natively go in `allowBuilds` (e.g. `better-sqlite3`, `prisma`).

## Naming

- Files are kebab-case, with Nest role suffixes (`.controller.ts`, `.service.ts`, `.client.ts`, `.module.ts`, `.spec.ts`).
- IDs follow Trestle's format: `VEN-`, `PRD-`, `PRM-`, `STF-`, `M-`. Overrides are `OVR-<n>`.
- Product words come from `docs/PRODUCT.md#glossary`.
